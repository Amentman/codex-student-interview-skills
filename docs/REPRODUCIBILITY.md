# 复现清单：怎样尽量得到相同效果

结论：只上传 `SKILL.md` 不能保证输出完全一致。Skill 能固定工作流、事实边界和验收门；最终结果还受模型、推理强度、提示词、工具、权限、输入证据、历史页面与随机性影响。目标应是“同样的判断边界与可验收质量”，而不是逐字相同。

## 已随仓库提供

- 六个相关 Skill、引用文档、脚本与现有自动测试。
- 原始全局提示词、原始校招项目提示词和可移植项目入口。
- 插件清单、GitHub 市场入口、安装说明与环境版本基线。
- 私有飞书节点和学生姓名的清理规则；仓库不携带生产凭据与真实学生材料。

## 仍需要提供或约定

### P0：不提供就无法稳定复现

1. **模型与推理档位。** 记录实际使用的模型 ID、reasoning effort，以及是否启用网页、文件、终端和多智能体。不同模型会影响篇幅、检索深度和工具决策。
2. **Codex 与工具版本。** 至少记录 Codex、lark-cli、Python、Node 与文档渲染工具版本；升级后先跑回归测试。
3. **飞书目标与权限。** 为每个部署环境提供目标知识库/父节点入口、命名约定、可写范围、允许的页面动作和只读保护对象。不要把凭据提交到 GitHub。
4. **输入合同。** 每次任务至少提供正式姓名、唯一简历、目标岗位/JD或真实面试逐字稿、已有飞书入口与本次交付对象。缺一项时按 Skill 的 `Open`/停止条件处理。
5. **提示词激活证据。** 验证用户级与项目级 `AGENTS.md` 都被加载，且没有 `AGENTS.override.md` 覆盖或默认 32 KiB 上限截断。

### P1：决定“像不像你”的关键材料

6. **2–3 套脱敏黄金样例。** 每套包含输入简历、JD/邀约/逐字稿、最终老师版、学生版或复盘页，以及为什么这样判断。样例应覆盖无 JD 通用模拟、真实公司专岗和真实面试复盘。
7. **反例与 Bad Case。** 提供至少一套“看似漂亮但不合格”的结果，标出事实越界、页面越界、题卡泛化、逐字稿压缩过度或读回不完整的位置。
8. **验收评分表。** 给路由、事实、结构、表达、飞书层级、附件、视觉和写后读回设硬门；同一黄金样例在新版本上复跑并记录差异。
9. **你的表达偏好样本。** 提供若干你认可的老师反馈、学生版大白话、题卡与任务卡，用来校准措辞、深度和篇幅；不要只给抽象形容词。

### P2：提高跨设备一致性

10. **渲染与字体环境。** 记录 Word/PDF/飞书最终查看器、字体和页面缩放；结构校验通过不能代替真实视觉验收。
11. **动态信息截止时间。** 公司、JD与经营信息必须记录检索日期，面试前按 Skill 重新核验；旧缓存不能当当前事实。
12. **隐私与脱敏规则。** 明确哪些学生字段能进入私有飞书、哪些能进入测试样例、哪些永不上传 GitHub。

## 推荐的复现验收

1. 在干净 Codex 环境安装插件与提示词，确认三类请求分别路由到通用模拟、专岗准备、真实面试复盘。
2. 使用同一套脱敏黄金输入，分别运行旧环境与新环境。
3. 比较事实账本、JD证据矩阵、题目目录、复盘证据定位、页面层级、附件和 `Open`；不要求逐字相同。
4. 对任何飞书写入重新读取完整 XML/Markdown、`revision_id`、父级、附件和渲染表面。
5. 只有硬门全部通过，才把新环境标为“行为等价”。
