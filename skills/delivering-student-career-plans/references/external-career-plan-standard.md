# 学生职业规划对外交付标准

## 三种模式

### 架构对焦

用户仍在讨论结构时，只输出：

1. 拟保留的 7—10 个章节；
2. 核心方向表与公司池表的字段；
3. 项目、简历、投递的先后关系；
4. 计划使用的 3—6 张解释图。

不得写完整正文，不写飞书，不补用户已删掉的章节。

### 标准学生版（默认）

目标是“紧凑完整”，不是长。学生看完能回答：投什么、日常做什么、为什么适合、薪资如何、公司有哪些、先补什么项目、什么时候做简历和正式投递。

标准学生版完成后默认写入飞书“职业规划”目录，飞书正文是主交付面；本地 Markdown、Word 或 PDF 是补充，不得用本地文件或单独附件代替飞书正文。例外仅限用户明确要求不写飞书或仍处于架构对焦阶段。

推荐结构：

1. **首屏结论与个人简历**：一句话主线、1—3 个可投方向、最重要的近期动作、原始简历附件。
2. **学生现状与求职目标**：只保留影响方向判断的教育、经历、城市、届别和待确认事项。
3. **核心求职方向总览**：方向、优先级、日常工作、为什么适合、可投岗位、关键补强、薪资参考。
4. **三个方向具体怎么选**：每个方向只展开日常工作、适配理由、代表岗位和进入条件；配一张工作流程图。明显暂不投的方向不占正文篇幅。
5. **行业与公司选择**：先解释岗位与行业的关系，再给每个方向的第一批公司、补充池、选择性冲刺/长期关注。
6. **补强项目**：通常 1—2 个，来自真实能力缺口；写最低可演示状态、最终交付和进入简历条件。
7. **简历版本规划**：项目达到最低证据门后制作对应版本；写主投岗位、突出内容和不应误写的内容。
8. **投递与面试策略**：正式投递批次、岗位筛选条件、反馈回流项目的方式。
9. **行动时间线**：项目、简历、投递和面试的里程碑，不把“并行推进”写成“项目没有证据也能先包装投递”。
10. **后续确认信息**：只保留会改变公司池、薪资判断或路线选择的学生信息。

相邻章节可合并。一个方向只有一句泛泛介绍、公司池没有公司名、薪资只写“有竞争力”、项目与岗位无关，均不算完成。

### 深度版

只有用户明确要求“完整深度版、详细版、全盘研究”时启用。可增加：

- 6—10 份代表性真实 JD；
- 逐段经历翻译与证据矩阵；
- 2—3 版简历；
- 分阶段实习/校招路径；
- 90 天计划和毕业前倒排；
- 更完整的风险、切换条件和执行分工。

深度版不是把标准版重复三遍。每一节都必须改变方向、项目、公司或投递判断；无决策价值的背景删除。

## 核心方向表

方向表必须出现在文档前 30%，建议字段：

| 优先级 | 核心方向与代表岗位 | 日常工作 | 为什么适合 | 关键补强 | 目标城市薪资参考 |
|---|---|---|---|---|---|

薪资写法示例：`上海，税前年包约 25—42 万；基于 2026-09-29 可见岗位样本，仅用于方向比较`。不能把单条高薪岗位写成市场平均，也不能只在正文末尾补一个薪资说明。

## 每个方向的写法

每个方向按同一阅读节奏：

1. 一句结论：在整个规划中承担什么角色；
2. 日常工作图：输入 → 任务 → 输出 → 协作/复盘；
3. 日常工作：大白话解释，不堆岗位名词；
4. 为什么适合：用学生现有经历证明，说明证据强弱；
5. 可以投：给出真实岗位名称和搜索关键词；
6. 补到什么程度可以投：写可检查的进入条件。

“为什么适合”不能只写专业对口，也不能把课程知识当成熟工作能力。岗位名称相似但工作对象不同的，明确边界。

## 行业与公司选择

先用一张岗位—行业矩阵说明：同一方向可以分布在哪些行业；不要把行业标签平铺成职业方向。

公司池表：

| 方向 | 第一批重点公司 | 补充公司 | 选择性冲刺/长期关注 | 当前使用方式 |
|---|---|---|---|---|

要求：

- 每格至少给出可核验的具体公司名称，数量服从证据，不凑名单；
- 明确哪些来自当前/近期岗位样本，哪些只是长期研究池；
- 大厂、中小厂、垂直场景公司按岗位匹配而非名气分层；
- AI Agent 方向单列大厂池时，至少说明应用开发/平台/评测与核心算法/后训练的门槛差异；同时保留中小型 AI/垂直场景主投池；
- 公司名单不得只出现在内部研究或最终回复中，必须写进学生正文。

具体岗位、资格和招聘时间在正式投递当天重新确认。动态边界集中说明一次，不在每行重复。

## 项目、简历与投递

正文顺序必须体现：

`项目补强 → 最小可演示证据 → 简历分版 → 正式投递 → 面试反馈 → 项目复测`

可以提前做公司/JD 研究和面试知识准备；不能把计划项目写进简历后直接投递。若学生已有一条成熟证据链，可先投对应岗位，同时继续补另一个方向，需明确区分。

每个项目至少包含：

- 状态和对应岗位；
- 场景、数据/权限边界；
- 核心模块与学生本人工作；
- 最低可演示证据；
- 最终交付与验收；
- 达标后进入哪版简历；
- 支持哪些面试追问和 Bad Case。

项目复杂度按岗位缺口决定。Agent 项目不能只停留在单次 API 调用：若目标岗位需要，应覆盖完整 RAG、可观察 Loop、多工具、记忆/状态、评测、日志和失败恢复；若岗位不需要，不为了显得复杂强塞模块。

## 图文阅读结构

常用视觉槽位：

- 方向优先级图；
- 每个方向的一张日常工作流程图；
- 岗位—行业匹配矩阵；
- 公司筛选漏斗或公司池分层图；
- 能力缺口—补强项目—求职证据关系图；
- 项目、简历、投递、面试的时间线。

一张图只回答一个问题。图中字号、节点、分支和终态必须可读；图注写明“看什么、学生下一步做什么”。不使用装饰图片。

## 外部表达

- 学生正文使用正式、大白话表达，不写生成过程、顾问自评、销售话术和内部事实标签。
- 首次出现的英文缩写紧接中文解释。
- 风险提示集中一次；未完成项目用“完成并通过复盘后，可加入对应简历版本”。
- 禁止出现 `Confirmed`、`Inferred`、`Open`、`HC`、`事实底稿`、`顾问判断`、`不包装成` 等内部语言。
- 不以字符数、章节数或页面数代替内容质量；删除空话，但不得删除日常工作、适配理由、公司名单、薪资、项目门槛和执行顺序。

## 完成检查

- 标准版 1—3 个可投方向均有日常工作、适配理由、岗位名、薪资和进入条件；
- 行业与公司独立成节，公司池包含具体名称与分层；
- 如含 Agent 方向，大厂与中小/垂直公司不会混成一列，算法门槛不会被绝对化；
- 项目章节位于简历和正式投递之前，并写明进入简历条件；
- 视觉内容就近放置，无裁切、压字或过小文字；
- 原始简历附件唯一、可预览、位于首屏或第一个编号章节之前；
- 飞书全文、附件、父级、唯一性和导出 PDF 均已回读验证。
