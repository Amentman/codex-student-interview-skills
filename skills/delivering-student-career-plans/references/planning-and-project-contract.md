# 方向、公司、项目与投递合同

## 方向选择合同

学生正文默认只展开 1—3 个可以投的方向。每个方向至少回答：

| 字段 | 要回答的问题 |
|---|---|
| 优先级 | 主攻、并行补充、条件性拓展或选择性冲刺？ |
| 日常工作 | 一天主要处理什么输入、完成什么任务、交付什么结果？ |
| 为什么适合 | 当前哪段经历或能力能迁移，证据强弱如何？ |
| 可以投什么 | 使用哪些真实岗位名称检索？ |
| 关键补强 | 缺什么可观察证据，补到什么程度才可投？ |
| 薪资参考 | 目标城市、税前年包/月薪、样本日期与样本性质是什么？ |

不要在每个方向后增加大段“为什么不适合/暂时不能投”。排除理由保留在内部台账；只有两个方向看似相近、学生很容易误选，或用户要求对比时，才用一句话说明边界。

## 行业与公司合同

行业/组织类型与岗位方向分开写。互联网、金融、外企、快消、央国企、研究机构不是六个独立职业方向；同一行业可同时存在 Agent 开发、模型评测和数据科学岗位。

每个方向建立公司池：

1. **第一批重点研究与投递**：岗位内容和学生证据最接近；
2. **补充公司池**：需要补一项关键证据或城市/组织条件略弱；
3. **选择性冲刺/长期关注**：岗位门槛更高或当前仅有历史样本。

公司池必须列真实公司名称，不能只写“中小厂/大厂/垂直公司”。动态信息分为：

- 当前或近期核验到的岗位样本：记录公司、岗位、城市、访问日、状态和来源；
- 长期研究池：只证明该公司值得持续检索，不暗示当前开放岗位。

AI Agent 方向存在时，额外检查：

- 是否单列大厂 Agent 池和中小型 AI/垂直场景公司池；
- 大厂中哪些是 Agent 应用开发、平台工程、RAG、评测，哪些偏基础模型、后训练、强化学习；
- 学生主投的是哪一类，哪些只做冲刺；
- 不能把“缺顶会论文”扩大成“大厂全部不能投”，也不能弱化核心算法岗的真实门槛。

## 薪资合同

- 薪资放在核心方向表，不藏到文末。
- 优先使用目标城市、应届/实习和相近职责的公开样本，写税前年包或月薪 × 薪数。
- 说明核验日期、样本数量/性质；单条 JD 只能称“岗位样本”，不能当市场平均。
- 比较 Offer 时提醒拆分固定薪资、奖金、股票、补贴、试用期工资和工作强度，但不要在规划中展开成薪酬百科。

## 项目与执行顺序

默认顺序：

`方向与岗位 → JD 证据 → 能力缺口 → 项目设计 → 最小可演示证据 → 简历版本 → 正式投递 → 面试复盘`

公司研究、岗位搜索和基础面试知识可提前进行；“先投再说”不是默认主流程。用户要求并行时，必须区分：已有经历可支撑的岗位可以先投，依赖新项目证据的岗位等项目达到简历进入条件再正式投。

项目数量服从明确范围。没有明确数量时，应届生通常 1—2 个；社招默认深挖既有项目/实习，不新增无法解释的训练项目。

每个项目必须回答：

- 对应哪个岗位和哪条缺口；
- 解决什么场景问题，数据和权限边界是什么；
- 学生本人完成哪些模块；
- 形成哪些代码、报告、Demo、评测或作品集；
- 最低可演示状态和最终验收分别是什么；
- 达到什么条件才进入哪一版简历；
- 支持哪些面试追问和失败案例复盘。

计划中、进行中和已完成必须分开。没有可检查产出前不生成成果型 bullet；团队方案、导师示例和目标指标不成为学生结果。

## 核心输出表

| 优先级 | 方向与代表岗位 | 日常工作 | 为什么适合 | 关键补强 | 目标城市薪资参考 |
|---|---|---|---|---|---|

| 方向 | 第一批公司 | 补充公司 | 选择性冲刺/关注 | 分层理由 | 样本核验日 |
|---|---|---|---|---|---|

| 项目 | 对应缺口 | 最小可演示证据 | 最终交付 | 进入简历条件 | 面试用途 |
|---|---|---|---|---|---|

同一条能力证据应贯穿项目、简历、岗位筛选和面试讲法，不能把四部分写成互不相干的建议。
