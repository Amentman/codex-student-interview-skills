# 飞书职业规划交付合同

## 部署时配置落点

每个使用者在自己的私有配置或当前任务输入中提供以下目标，禁止把真实空间 ID、父节点 token 或个人飞书 URL 提交到 Skill/GitHub：

| 目标 | 建议标题 | 配置方式 |
|---|---|---|
| 空间 | 校招交付 | 当前任务提供空间 URL/token，运行时解析 `space_id` |
| 根节点 | 校招交付 | 当前任务提供根节点 URL/token，写前重新读取 |
| 知识父节点 | 求职策略与知识库 | 仅明确交付白皮书时提供并核验 |
| 白皮书目录 | 行业白皮书与岗位科普 | 每次列表查找或创建后记录 token |
| 个人规划父节点 | 职业规划 | 当前任务提供父节点 URL/token，写前重新读取 |

白皮书命名：`行业/赛道｜行业与岗位白皮书（YYYY版）`。个人规划命名：`姓名｜主攻方向职业规划（届别）`；未知字段直接省略，不用占位符。

## 写前验证

1. 使用 `lark-cli ... --as user`。
2. 解析当前任务提供的根节点和职业规划父节点，并执行 `wiki +node-get`，核对标题、token 和 `space_id`；只有用户明确要求白皮书时，再核对知识父节点。
3. 只有实际交付白皮书时，才列出知识父节点的子节点，精确复用或创建“行业白皮书与岗位科普”。
4. 列出职业规划目录的同名页；实际交付白皮书时再列白皮书目录。存在时先读取，判断更新、复用或创建明确版本，不能静默重复。
5. 任一父节点或空间不匹配时停止写入；不要凭缓存 token 猜测。

## 写入顺序

用户仍在讨论架构、要求先对焦或明确不要输出时，不进行飞书写入。用户直接要求制作、完善或交付职业规划，即视为授权把最终学生版写入飞书“职业规划”目录；无需等待用户再次单独说“写到飞书”。只有用户明确要求本地交付或不写飞书时才跳过。进入最终交付后：

1. 读取现有页面的完整结构、revision、附件和已确认内容；
2. 若已有完整 PDF、Word、Markdown 或已确认飞书稿，先把它登记为受保护母版；按母版章节和信息顺序串行写入，不得先另写一份摘要再据此转换；
3. 只创建或更新个人规划骨架，按“方向与公司 → 项目 → 简历 → 投递 → 时间线”串行写入；
4. 用个人规划的 `obj_token` 上传原始简历，在“个人简历”标题后、第一个编号章节之前插入真实文件块；已有简历图片可保留，但不能代替文件块；
5. 只有用户明确要求白皮书时，才创建或更新白皮书，并在个人规划文末提供自然的“延伸阅读”；不要默认把白皮书链接放到页首；
6. 需要保留已有 PDF 白皮书时，用白皮书 `obj_token` 插入原文件，不重写二进制资产。

长文使用 XML 或 CLI 推荐的结构化格式，按“骨架 → 分章节 → 附件 → 位置调整”串行更新。已有页面先完整读取并保护定制内容；局部补充公司名单、薪资或项目时使用 block ID 精准更新，不整篇覆盖。只有确认空白时才整体覆盖。导入 Markdown/Word 后要另行检查附件位置；导入器默认追加到文末时，必须移回首页。

## 写后读回

分别执行完整正文读取和目录读取，检查：

- 如实际交付白皮书，它是“行业白皮书与岗位科普”的直接子页；
- 个人规划是“职业规划”的直接子页；
- 完整规划正文实际存在于飞书文档中；本地 Markdown、Word、PDF 或仅上传一个附件都不能替代正文写入；
- 实际交付文档标题、核心章节、更新时间和来源存在；
- 如实际交付白皮书，个人规划中的延伸阅读链接正确；未交付时不要求链接；
- 核心方向表含日常工作、适配理由、代表岗位和薪资；
- 公司池包含每个方向的具体公司名称和分层；AI Agent 方向适用时，大厂池与中小/垂直池均存在；
- 项目章节位于简历版本和正式投递之前；
- 原始简历以唯一的 `<source>`/`file` 文件块存在，文件名正确，位于第一个编号章节之前，并已实际打开预览；
- 已有白皮书 PDF 迁移时，PDF 附件可读回且文件名正确；
- 页面不是空壳、没有重复页、没有覆盖原有定制内容。
- `text_path` 指向本轮从飞书读回的完整正文，不是人工整理的摘要；其 SHA-256 与读回 JSON 的 `markdown_sha256` 一致。
- 有受保护母版时，章节、数字、公司名、来源链接/编号、行动链条与必需图示逐项通过；每个必需图示都能读回非空媒体 token。

把 wiki token、obj token、父 token、URL、读取时间、附件文件名和验证结果写入交付 manifest，并另存一份读回 JSON。详见 `delivery-manifest-schema.md`。只有写后读回成功，才能报告“已写入飞书”。

直接父节点必须由飞书当前状态独立证明，不能读取 manifest 后自报一致：优先保存 `wiki +node-get` 的父 token；用浏览器时同时保存子页和父页的 `data-node-level`、`data-node-pos` 与 `wikiToken`，并验证子页层级恰好比父页深一层、子页位置只比父页位置多一个末级索引。

文件名出现在正文、DOM 或截图中，只证明“看到名称”。必须进一步确认块类型、首页位置和预览可打开性。若更新中附件块意外变成图片或消失，保留现有图片并把原文件块恢复到“个人简历”标题后；下载回读文件并与本地原件核对大小和 SHA-256。
