# 学生模拟面试交付

**先分流：** 用户已有明确公司、岗位、JD 或面试邀约并要求面试前定向准备时，使用 `student-role-interview-prep`；用户提供真实已发生面试的录音、转写稿或问答记录并要求复盘时，使用 `student-interview-review-delivery`。本 Skill 只处理通用模拟面试。用户同时要求多类交付时分别确定写入对象，不把专岗或复盘内容插入通用双端正文。

飞书是默认正式交付物，但本 Skill 不授予额外写入权限：只有用户当前请求或会话已有授权明确包含飞书交付时，才创建或更新学生主页、老师版和学生版；“先分析／只在聊天回答／不要写飞书”时保持只读。正式飞书交付不生成持久的本地母稿、双端 Markdown、交付索引、备份目录或画板验收目录。用户给出的简历只读原路径，不复制进学生目录。只有用户明确要求“导出／保留本地副本”时，才进入可选本地导出模式。

本 Skill 只处理通用面试理解、出题、训练与飞书双端交付。简历或旧页出现“作品集”不代表授权策划作品集、新设训练项目或研究 GitHub 参考；用户未明确把作品集纳入本次范围时，新增正文、面试题和任务卡都不展开作品集。

按顺序执行，遇到参考文件定义的停止条件立即说明候选项或限制；不得猜测学生事实或变更权限。正常交付绝不删除飞书内容，也不得在可分发 Skill 中写死某个组织的空间、页面或历史清理令牌。

## 先读与准备

本文中的 `scripts/...` 均相对本 Skill 目录解析，并统一使用 `python3` 执行。若不在本 Skill 目录运行，先解析 Skill 的绝对路径；不得依赖调用者当前工作目录。`locate_student.py` 的默认目录只适用于原 macOS 环境，其他机器或目录结构必须显式传一个或多个 `--root <交付根目录>`。

1. 阅读 [interview-content-contract.md](references/interview-content-contract.md)、[interview-quality-contract.md](references/interview-quality-contract.md)、[interview-session-contract.md](references/interview-session-contract.md) 与 [feishu-delivery-contract.md](references/feishu-delivery-contract.md)。仅当用户明确要求本地副本时，再读 [local-output-contract.md](references/local-output-contract.md)。
2. 使用 `building-resume-interview-stories`。按简历格式先使用 PDF Skill（PDF）或 documents Skill（DOCX）；按各 Skill 的渲染／版面检查规则解析原件。若格式 Skill 需要渲染或解包，必须把所有中间文件定向到本任务专属的系统 `mktemp -d` 目录，并在验收后清理；不得使用固定 `tmp/`、`tmp/pdfs/`、工作区或学生目录。格式 Skill 的通用输出示例不能覆盖本 Skill 的飞书唯一交付约束。
3. 在调用对应 CLI 域之前，阅读该环境中版本匹配的 `lark-wiki`、`lark-doc` 和 `lark-drive` 嵌入指南；只在需要的域操作前读取其指南。

## 交付流程

1. 解析输入。用户给出简历或转写稿路径时直接只读原件；用户只给姓名时，可运行只读的 `python3 <本 Skill 目录>/scripts/locate_student.py --name <姓名> [--root <交付根目录>]` 寻找候选资料，但不得创建学生目录或复制文件。迁移环境必须显式传 `--root`。主简历、姓名或转写稿归属不唯一时停止并列出冲突。
2. 先做飞书预检。运行 `python3 <本 Skill 目录>/scripts/feishu_page_titles.py --name <姓名>`，按飞书合同解析／复用唯一学生主页与双子页；同一角色的新旧标题合计只能命中一页，旧标题只原地重命名。更新已有页前读回完整 XML 并记录当前 `revision_id`／历史版本作为恢复点；同时在当前任务中建立“保留清单”，列出已有章节、三档匹配 JD 的岗位与字段、指标扫盲条目、附件与媒体 token、导师／学生手工内容。“整体重做”允许重组标题、层级和排版，但岗位信息、手工内容、附件与有效媒体必须迁移到新结构并逐项读回；不强行保留已被同义替换的旧空壳、重复表或坏结构。
3. 解析简历，建立事实账本：`Confirmed`、`Externally verified`、`Inferred`、`Knowledge supplement`、`Open`。只将 `Confirmed` 写成候选人亲历；外部事实附来源和检索日期；动态 JD 标示时效；无真实 JD 时明确标记为代表性岗位画像／示例 JD。随后先形成 `JD逐条证据矩阵` 与 `个性化锚点清单`，不得从通用题库或姓名替换开始。
4. 按场次合同给目标岗位最相关经历做 0–3 级口述评分，选择“履历讲解／结构化训练／完整模拟／JD 定向模拟”；再按目标岗位选择 `business`、`product`、`technical` 或 `mixed` 路线。运营、市场、电商、商业分析等岗位优先使用 `business`，不得为了显得先进而强塞 AI 产品路线。未确认的求职意向记为 `Open`，不得按姓名或学校猜测。
5. 在当前任务中形成老师版与学生版内容，完成写入前人工质量门后直接写入飞书，不先生成本地母稿。两端使用同一套个性化题目目录：老师版按“快速上手—三档匹配 JD 与证据—履历拆解—项目与指标—项目架构—模拟流程—题卡—反馈”组织；学生版按“使用说明—核心定位—三档匹配 JD—项目与术语—指标口径扫盲—项目架构—题卡—任务”组织。**标准版固定使用一个 `三档匹配 JD` 章节和三张 JD 卡：`90%｜主投｜岗位名`、`80%｜稳妥拓展｜岗位名`、`70%｜进阶尝试｜岗位名`。三档就是三张 JD，一一对应且两端岗位与顺序一致；不得再拆出 `三档岗位画像` 或 `主要岗位／JD卡`。**每张卡必须同时包含 `岗位日常`、`匹配证据`、`差距`、`档位原因`、`投递建议`。历史页若已有额外岗位卡，把仍有效的信息并入最接近的档位；无法合并的冲突标成 Open，不保留重复的第二个岗位章节。所有进入 JD、项目、数值成果或题卡的关键指标都要在“指标口径扫盲”找到对应卡，并且总数不少于 3 张；常见业务指标由校验器直接识别，非常见或自定义口径首次出现时写成 `【指标：名称】`，确保跨章节逐项核对而不是只数卡片。问题之前先完成 `Pxx` 深挖卡、项目地图、数值反推、职责边界、指标小白解释、可验收产物和必要图解。页面原生标题是唯一 H1；参考模板只用 Confirmed 事实预填，Open 保留请补项。
6. 写入前先完成整页排版计划，**REQUIRED SUB-SKILL:** Use `visual-document-delivery` 处理通用的图形选择、`visual_contract` 和最终渲染术语；本 Skill 的双端边界、问题区前置、媒体 token、保留清单和飞书读回规则更严格时，本地规则优先。每个前置章节只服务一个阅读任务，项目段落按“结论短段—证据短表／卡片—就地图解（需要时）—职责边界”混排，不能前半段连续堆长表、后半段集中堆图。用户点名要图的项目，以及包含多角色／多系统协作、分支判断、循环回流、失败回退的核心链路，一律视为必需图；普通定义和简单线性步骤可用段落或短卡。同一页的图使用一致的阅读方向、角色颜色语义和标题层级。图解先在专属临时目录成功生成并导出可读预览，再插入正式页；失败时不插入占位、空 token 或坏图，必需图未成功时交付状态仍为未完成。
7. 直接从原始简历路径上传附件到两份子页，并确认它是标题后的第一个正文块；不把简历复制进交付目录。更新已有页面时仅替换本次请求涉及的区块，保留用户／导师手工内容。长内容按可读章节分批写入，每批后立即局部读回；任一批失败就停止，不用新建页面绕过旧页。
8. 写完后运行 `python3 <本 Skill 目录>/scripts/validate_feishu_delivery.py --name <姓名> --homepage <主页URL/token> --internal <内部页URL/token> --student <学生页URL/token> --track business|product|technical|mixed [--forbid-name <姓名>]`。校验器直接从飞书读取 Markdown 和完整 XML，检查两端三档匹配 JD 是否同章、一一对应、字段齐全且岗位顺序一致，以及指标扫盲卡与字段、跨章节指标覆盖、图解在面试前、未解决图片占位、空媒体 token、既有标题、入口、附件、事实、路线、题目和学生端泄漏规则；失败时修正飞书并复跑。
9. 自动校验通过后，再读回主页和两份子页，用保留清单逐项对比章节、三档匹配 JD、指标扫盲、附件、媒体 token 与手工内容；人工确认老师能直接主持、学生按“先懂岗位—再懂项目—最后练题”阅读，页面无重复的档位／JD区块、“前表后图”、坏图或图片墙。本次新增或更新的每张图都要逐张目视验收。若 CLI 必须用文件承载超长正文或预览，只能用 `mktemp -d` 创建任务专属临时目录，验收后只清理该精确目录，并确认路径已不存在。
10. 最终只交付飞书主页、内部版、学生版链接，以及全部 `Open` 与无法验证项；明确报告 URL 是否变化、远端校验的 `revision_id` 和图解验收结果。不交付本地文件链接。

## 边界

不要自动投递、公开发布、修改飞书权限／所有权／外部分享设置，或删除用户原始资料与飞书内容。不要按姓名推断学校、专业、性别或求职意向。用户明确要求本地副本时，才读取本地输出合同并额外交付；这一例外不得反向成为默认流程。
