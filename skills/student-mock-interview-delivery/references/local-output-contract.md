# 可选本地导出合同

本合同不是默认流程。只有用户明确要求“导出本地文件”“保留 Markdown／PDF／DOCX 副本”时才读取和执行。普通模拟面试交付以飞书为唯一正式产物，不创建本地母稿、老师版、学生版、交付索引、备份目录或画板验收目录，也不复制简历。

进入本地导出模式后，本地交付根目录由 `scripts/locate_student.py` 确定，不再写死单一路径。老师版／母稿固定为 `<交付根目录>/<姓名>/<姓名>_模拟面试.md`，学生版固定为 `<交付根目录>/<姓名>/<姓名>_学生面试准备版.md`。真实面试后的复盘由 `student-interview-review-delivery` 单独处理。

## 输入与定位

- 根目录解析：用户明确提供交付根目录时使用 `--root` 并原样尊重；否则检查桌面下有限深度内所有名为“校招交付”的目录。只有一个现存根目录时直接使用；有多个时，仅当其中唯一一个包含该学生同名目录或姓名简历证据时使用。没有根目录返回 `missing_root`；仍有多个候选返回 `ambiguous_root` 并停止，绝不按最近修改时间或旧硬编码路径猜选。
- 用户给简历：优先采用明确姓名；未给姓名时交叉比对文件名与正文，冲突即停止。先运行定位脚本确定交付根目录，再找完全同名目录；没有才在已确定根目录下新建。复制外部简历到目录，绝不移动或删除原件；不同内容的同名文件不覆盖，保留候选并要求选择主简历。
- 用户只给姓名：运行 `scripts/locate_student.py --name <姓名>`，先找已确定根目录下完全同名一级文件夹，再找全路径文件名含姓名的简历。唯一才使用，多个则列出候选，无结果则索取简历。
- 支持 PDF、DOCX。使用格式对应 Skill 解析并检查原始版面。
- `scripts/locate_student.py` 只读：绝不创建、复制、移动、重命名或删除用户路径。其 JSON 提供 `status`、`student_name`、`delivery_root`、`root_candidates`、`root_resolved_by`、`student_dir`、`resume_candidates`、`primary_resume`、`interview_markdown`，路径为绝对路径；`ok`/0、`ambiguous`/2、`missing`/3、`invalid_name`/4、`missing_root`/5、`ambiguous_root`/6。

## 更新与校验

- 更新母稿时保留用户或导师手工内容，只改本次请求直接相关的段落。
- 原始简历必须存在，且老师版前 25 个非空行内有精确简历文件名的链接；老师版包含岗位判断、履历大白话、事实与职责边界、项目图解、主持流程、逐题判断与带教；学生版包含三张主要岗位／JD卡、至少三张指标口径扫盲卡、项目与行业输入、题前项目图解、逐题半成品模板、个人逐字稿填写区和面试前任务。两端题目标题、分类和顺序必须一致。
- 默认不得出现其他学生姓名；仅在明确标记的比较案例中例外。数值型候选人成果须可追溯至事实账本来源。
- 新交付必须先选 `business`、`product`、`technical` 或 `mixed`，运行 `scripts/validate_delivery.py --name NAME --resume RESUME --master MASTER --track TRACK [--internal INTERNAL] [--student STUDENT] [--post-session REVIEW] [--forbid-name NAME]`。老师版同时作为母稿时，`MASTER` 与 `INTERNAL` 可以指向同一文件。省略 `--track` 只为兼容旧调用，不代表新交付可跳过路线选择。
- 校验器输出 JSON。成功为 `{"status":"ok","errors":[]}`、退出 0；失败为 `{"status":"invalid","errors":[...]}`、退出 1。它校验老师版、学生版、岗位路线、可选复盘、姓名、简历链接、三档岗位字段、主要岗位／JD卡、指标口径扫盲卡及跨章节指标覆盖、JD 证据矩阵、经历卡、题前图解、未解决图片占位、双端问题分类与顺序、题卡字段、学生模板长度和内部信息泄漏；复盘检查必需板块与未脱敏手机号。
- 本地导出文件必须通过本地校验器后才能交付，但它们不是飞书写入的前置条件。飞书是否完成只以远端校验与最终读回为准；本地通过不能替代远端读回。

停止并询问：学生／主页或主简历不唯一、姓名冲突、会覆盖来源不明的手工内容。
