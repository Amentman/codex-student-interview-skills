# 飞书交付合同

在使用任何相关 CLI 域前，阅读版本匹配的 `lark-wiki`、`lark-doc`、`lark-drive` 嵌入指南。

## 飞书直写原则

- 飞书主页、老师版、学生版和可选复盘是默认且唯一的正式交付物；不先生成本地 Markdown，也不创建本地索引、备份或验收目录。
- 用户提供的简历从原路径直接读取、解析和上传，不复制到学生目录。原始资料只读，不移动、不覆盖、不删除。
- 更新已有页前读回完整 XML，并把当前 `revision_id`／历史版本记录在当前任务状态中作为恢复点；飞书历史替代本地备份文件。
- 同步建立不落盘的保留清单：章节标题与顺序、三档匹配 JD 的岗位与字段、指标扫盲条目、附件、媒体 token、导师／学生手工内容。“整体重做”可以删除已被同义替换的旧空壳、重复表或坏结构，但岗位信息、手工内容、附件与有效媒体必须迁移到新结构；除此之外只有用户明确要求删除时才能移除。
- 正文直接写入飞书。若 CLI、PDF 或 DOCX 解析因参数长度、渲染、解包或画板预览必须落盘，只能使用 `mktemp -d` 生成任务专属临时目录；验收后只删除这个精确临时目录，不使用固定 `tmp/`、`tmp/pdfs/`，也不在工作区、学生目录、`$HOME` 或 `~` 下保留产物。
- 用户明确要求本地副本时，才额外执行本地输出合同；本地副本不是飞书写入的前置条件。

## 目标节点和结构

- 不在可分发 Skill 中写死某个组织的 `space_id` 或页面 token。
- 优先使用用户提供的飞书入口；未提供时，通过当前已授权的知识库搜索定位唯一“校招交付／模拟面试”节点。
- 候选空间、节点或学生主页不唯一时停止写入，列出冲突并只问一个必要问题。
- 内部子页标准标题：`<姓名>｜面试指导者版（内部）`
- 学生子页标准标题：`<姓名>｜学生面试准备版`

准备型材料唯一允许的结构：

```text
校招交付
└── 模拟面试
    └── <姓名>
        ├── <姓名>｜面试指导者版（内部）
        └── <姓名>｜学生面试准备版
```

学生主页是普通飞书文档，标题只能是姓名，正文仅写交付索引与两份子页用途说明，不放简历或题目；用途说明中引用的子页名称也必须使用上述带姓名、无编号的标准标题，不保留“可分享”字样。两份子页的标题后第一个正文块必须是原始简历附件或文件卡片。

## 预检、更新与迁移

1. 在“模拟面试”直属子节点按完全同名标题寻找主页：一份复用、没有创建、多份停止报告。根目录是否存在不再是飞书交付的前置条件。
2. 运行 `scripts/feishu_page_titles.py --name <姓名>` 取得标准标题与旧标题迁移别名。内部版同时匹配标准标题和旧标题 `01｜面试指导者版（内部）`；学生版同时匹配标准标题和旧标题 `02｜学生面试准备版（可分享）`。同一角色的新旧标题合计一份则复用，零份才按标准标题创建，多份立即停止报告。命中旧标题时只原地重命名，绝不可用“新建再删除旧页”替代，以保留 URL、附件、历史。
3. 更新已有页面前读回主页和两子页的完整 XML，记录页面 token、URL、`revision_id` 和可用历史版本；在当前任务状态中建立保留清单，尤其逐档记录已有三档匹配 JD、指标扫盲、附件和媒体 token。这是恢复点，不另存本地备份。确认每名学生恰有两份目标文档，学生版没有内部内容。
4. 通过写入前人工质量门后，把老师版与学生版直接写进目标页面；只改本次请求涉及的区块。简历从原始路径直接上传，并放在两份子页标题后的第一个正文块。长文分章节写入，每批后局部读回；失败时停止，不创建替代页掩盖失败。
5. 写完后运行 `scripts/validate_feishu_delivery.py` 直接读取主页和双子页；只有返回 `status: ok`，且三个 `revision_id` 与本轮最新读回一致，才进入人工画板验收。自动校验失败时直接修正目标飞书页面并复跑，不通过不得宣称完成。
6. 最终再次读回主页和两子页，先用保留清单逐项对比，再验证附件、内容边界、页面树与 URL；发现旧岗位卡、指标扫盲、附件、媒体或手工内容未经授权消失，或学生版泄漏内部信息时，立即修正并复验。CLI 写入成功不等于交付完成。
7. 迁移旧标题或旧分类时只做当前用户明确授权的对象；先记录原 URL、父级、附件和手工内容，原地移动或重命名后逐页读回。正常交付不删除节点；接口不支持移动、重命名或读回失败时停止。

## 正文与画板质量

- 页面原生标题已经承担 H1 语义，正文不得再次插入同名或近似同名的一级标题。
- 附件后的首屏只保留一个结论型引用块和一张紧凑导航表；后续按“结论短段—证据短表／卡片—就地图解—边界说明”稳定混排，不堆叠多组长表或在后半段集中放图片。
- 项目图解或架构画板必须位于模拟面试问题之前。老师版与学生版可以分别使用适合其读者的画板，但学生版不得出现内部评分、追问答案或核查备注。
- 图解必须先在本任务唯一的系统临时目录成功生成、导出并目视确认，然后才能插入正式飞书页。失败时不得插入占位文字、空 token、坏链接或零尺寸图像；必需图未成功时，整项交付仍为未完成。
- 每张本次新增或更新的画板都必须完成两层验收：一是读回文档 XML，核对画板块数量、顺序、token 与所在章节；二是导出预览并逐张目视检查字号、裁切、重叠、连线、方向与正常桌面缩放下的可读性。仅有 API 成功回执不能算画板验收完成。
- 画板逐张通过后，再把老师版和学生版导出为 PDF 或等价的完整学生可见渲染，逐页检查裁切、跨页断裂、表格宽度、最小字号、图文分离和阅读顺序。任一页失败时修正并重新导出，从第一页重新检查；页数、已检查页和问题记录写入 `visual_contract.render_qa`。
- 飞书最终读回还要确认：附件仍是第一个正文块、老师版图解在模拟面试流程前、学生版图解在问题前、两端都只有一个 `三档匹配 JD` 章节且三张卡一一对应、指标扫盲完整、无未解决图片占位或空媒体 token、题数与两端顺序一致、正文无重复 H1、学生版无内部字段。

不得公开发布、改权限、改所有权或外部分享设置。一次性删除例外不得重用，任何未来运行都不得删除飞书节点。
