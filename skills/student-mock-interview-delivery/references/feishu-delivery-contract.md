# 飞书交付合同

在使用任何相关 CLI 域前，阅读版本匹配的 `lark-wiki`、`lark-doc`、`lark-drive` 嵌入指南。

## 飞书直写原则

- 飞书学员档案、老师版、学生版和可选复盘是默认且唯一的正式交付物；不先生成本地 Markdown，也不创建本地索引、备份或验收目录。
- 用户提供的简历从原路径直接读取、解析和上传，不复制到学生目录。原始资料只读，不移动、不覆盖、不删除。
- 更新已有页前读回完整 XML，并把当前 `revision_id`／历史版本记录在当前任务状态中作为恢复点；飞书历史替代本地备份文件。
- 同步建立不落盘的保留清单：章节标题与顺序、三档匹配 JD 的岗位与字段、指标扫盲条目、附件、媒体 token、导师／学生手工内容。“整体重做”可以删除已被同义替换的旧空壳、重复表或坏结构，但岗位信息、手工内容、附件与有效媒体必须迁移到新结构；除此之外只有用户明确要求删除时才能移除。
- 正文直接写入飞书。若 CLI、PDF 或 DOCX 解析因参数长度、渲染、解包或画板预览必须落盘，只能使用 `mktemp -d` 生成任务专属临时目录；验收后只删除这个精确临时目录，不使用固定 `tmp/`、`tmp/pdfs/`，也不在工作区、学生目录、`$HOME` 或 `~` 下保留产物。
- 用户明确要求本地副本时，才额外执行本地输出合同；本地副本不是飞书写入的前置条件。

## 部署配置和结构

每个使用者通过私有配置或当前任务输入提供并核验以下目标；分发版 Skill、测试夹具和公开仓库不得写入真实空间 ID、节点 token 或个人飞书 URL：

- `space_id`
- 校招交付根节点
- 学员交付知识库节点
- 学员档案总目录节点
- 旧“模拟面试”目录节点（如该部署存在；只用于查重和迁移判断，不再作为新交付父级）
- 内部子页标准标题：`<姓名>｜面试指导者版（内部）`
- 学生子页标准标题：`<姓名>｜学生面试准备版`

准备型材料的目标结构（没有第二层同名主页）：

```text
校招交付
└── 学员交付知识库
    └── 学员档案
        └── <姓名>（学员档案；正文末尾设“模拟面试交付入口”）
            ├── <姓名>｜面试指导者版（内部）
            └── <姓名>｜学生面试准备版
                └── <姓名>｜模拟面试复盘｜YYYY-MM-DD（有真实场次时可选）
```

同名学员档案已承载个人当前状态、历史与交付入口，不另建只写两份子页用途的同名主页。双端直达链接写入档案正文末尾的唯一“模拟面试交付入口”章节；旧索引页保留原 URL 供回溯，不复制为新的索引页，也不擅自删除。两份面试子页的标题后第一个正文块必须是原始简历附件或文件卡片。专岗与真实复盘按各自合同继续放在学生版下，不随本次层级精简散落到档案根层。

## 预检、更新与迁移

1. 先在“学员档案”按完全同名标题定位唯一学员档案，并用简历正文、主表或用户确认核实身份；同名多份、姓名与来源冲突时停止。若尚无档案，只有身份和归属已经核实且本次交付确需新建时，才先创建唯一档案。把它作为唯一的学生主页和面试交付父级；在档案直属子节点查找老师版、学生版，同时只读检查同名中间页与旧“模拟面试”目录。若角色页只存在于旧中间页下，先核对身份、同名重复项和子页，再按本次已授权的迁移范围移动原节点；直属层已有同角色页时停止报告重复。未获迁移授权时停止并报告，不创建替代页面。身份或归属不明的旧页保留为 Open。
2. 运行 `scripts/feishu_page_titles.py --name <姓名>` 取得标准标题与旧标题迁移别名。内部版同时匹配标准标题和旧标题 `01｜面试指导者版（内部）`；学生版同时匹配标准标题和旧标题 `02｜学生面试准备版（可分享）`。先在档案直属层按角色查重，再只读检查旧同名中间页和旧“模拟面试”目录是否仍有活跃同角色页。直属层每个角色恰好一份、旧位置没有活跃同角色页时直接复用；直属层多份，或直属层与旧位置同时有活跃同角色页时立即停止报告重复，不擅自覆盖、删除或合并。直属层缺少某角色时，仅有旧层级一份页面且本次明确授权迁移，才先移动原节点到档案直属层再复用；未获迁移授权或旧位置多份则停止报告；确认所有旧位置均无同角色页面时才新建。已搬到旧“模拟面试”目录的空历史索引页不计入活跃角色页数量。命中旧标题时只原地重命名，绝不可用“新建再删除旧页”替代，以保留 URL、附件、历史。
3. 更新已有页面前读回学员档案和两子页的完整 XML，记录页面 token、URL、`revision_id` 和可用历史版本；在当前任务状态中建立保留清单，尤其逐档记录已有三档匹配 JD、指标扫盲、附件和媒体 token。这是恢复点，不另存本地备份。确认每名学生恰有两份目标文档，学生版没有内部内容。
4. 通过写入前人工质量门后，把老师版与学生版直接写进目标页面；只改本次请求涉及的区块。简历从原始路径直接上传，并放在两份子页标题后的第一个正文块。长文分章节写入，每批后局部读回；失败时停止，不创建替代页掩盖失败。双端就绪后，在原学员档案正文末尾创建或局部更新唯一的“模拟面试交付入口”二级标题和两条直达链接；只附与该学员已核实归属的复盘／专岗等关联链接，不从旧索引页照搬未经核实的事实。不得为这段简短说明新建页面。
5. 写完后运行 `python3 <本 Skill 目录>/scripts/validate_feishu_delivery.py --profile <学员档案Wiki URL> --internal <老师版Wiki URL> --student <学生版Wiki URL> --space-id <空间ID> --archive-root <学员档案总目录token> --old-mock-root <旧模拟面试目录token>`（其余参数见主 Skill）；校验器直接读取档案和双子页，并核对两端均为档案直属子页、档案总目录没有同名档案、目标档案下没有同名中间页、旧目录没有活跃同角色页，以及台账末尾唯一入口的双端链接。只有返回 `status: ok`，且三个 `revision_id` 与本轮最新读回一致，才进入人工画板验收。自动校验失败时修正目标页并复跑，不通过不得宣称完成。
6. 最终再次读回学员档案和两子页，先用保留清单逐项对比，再验证附件、内容边界、页面树与 URL；发现旧岗位卡、指标扫盲、附件、媒体或手工内容未经授权消失，或学生版泄漏内部信息时，立即修正并复验。CLI 写入成功不等于交付完成。
7. 历史一次性迁移或清理授权不进入可复用合同，不得据此再次删除任何节点。旧“模拟面试”目录如存在，只用于历史索引、待归属资料和查重，不用作新交付入口。未来每次交付仍实时查重，不把某次迁移数量当成当前状态。

## 正文与画板质量

- 页面原生标题已经承担 H1 语义，正文不得再次插入同名或近似同名的一级标题。
- 附件后的首屏只保留一个结论型引用块和一张紧凑导航表；后续按“结论短段—证据短表／卡片—就地图解—边界说明”稳定混排，不堆叠多组长表或在后半段集中放图片。
- 项目图解或架构画板必须位于模拟面试问题之前。老师版与学生版可以分别使用适合其读者的画板，但学生版不得出现内部评分、追问答案或核查备注。
- 图解必须先在本任务唯一的系统临时目录成功生成、导出并目视确认，然后才能插入正式飞书页。失败时不得插入占位文字、空 token、坏链接或零尺寸图像；必需图未成功时，整项交付仍为未完成。
- 每张本次新增或更新的画板都必须完成两层验收：一是读回文档 XML，核对画板块数量、顺序、token 与所在章节；二是导出预览并逐张目视检查字号、裁切、重叠、连线、方向与正常桌面缩放下的可读性。仅有 API 成功回执不能算画板验收完成。
- 画板逐张通过后，再把老师版和学生版导出为 PDF 或等价的完整学生可见渲染，逐页检查裁切、跨页断裂、表格宽度、最小字号、图文分离和阅读顺序。任一页失败时修正并重新导出，从第一页重新检查；页数、已检查页和问题记录写入 `visual_contract.render_qa`。
- 飞书最终读回还要确认：附件仍是第一个正文块、老师版图解在模拟面试流程前、学生版图解在问题前、两端都只有一个 `三档匹配 JD` 章节且三张卡一一对应、指标扫盲完整、无未解决图片占位或空媒体 token、题数与两端顺序一致、正文无重复 H1、学生版无内部字段。

不得公开发布、改权限、改所有权或外部分享设置。历史删除例外不得重用，任何未来运行都不得删除飞书节点。
