# 模拟面试深度质量合同

本合同防止“篇幅很长但无法使用”。已有学生版本、历史模板和参考网页都只能提供线索，不能自动成为质量基准；每次交付都要回到老师怎样上课、学生怎样训练以及当前学生有什么真实证据。

## 一、先做证据工程

1. 将目标 JD 逐条拆成能力要求，标记 `直接证据`、`可迁移证据` 或 `缺口`。
2. 建立个性化锚点：

```text
- E01｜Confirmed｜简历｜经历名称：真实动作或产物
- J01｜Externally verified｜目标 JD｜岗位要求
- K01｜Knowledge supplement｜行业知识｜只能帮助理解
- O01｜Open｜待确认｜会改变故事主线的关键事实
```

3. 所有候选人动作、数据和结果都回到锚点；不能从通用题库开始，再做姓名替换。
4. 关键 `Open` 会改变职责或结果时，参考模板必须保留请补项，不得生成完整成稿。

## 二、核心经历要能抗追问

每段核心经历都应沿以下链路讲通：

`业务问题 → 输入 → 个人动作 → 产物 → 数字／结果 → Bad Case → 取舍 → 职责边界`

“参与、协助、负责优化”不是有效个人动作。应继续追到候选人处理了什么信息、做了什么判断、交付了什么东西、如何验证。没有证据的工具名、流程、指标和业务结果一律不得补写。

## 三、老师端的完成标准

不熟悉该岗位的老师只看文档，也应能：

- 用大白话复述每段核心履历到底做了什么、为什么有价值。
- 说明岗位核心能力与候选人证据的对应关系。
- 按 60 分钟左右的流程选择题目，而不是从几十道题里临时翻找。
- 对每题判断“是否合格”，并沿动作、产物、数据、Bad Case 和职责边界继续追问。
- 现场给出具体反馈和课后作业，而不是只说“再具体一点”“多练习”。

老师版不得变成大段自然参考答案堆积。参考回答方向是判断标尺，候选人素材和继续追问才是主持面试的核心。

## 四、学生端的完成标准

学生只看文档，也应能：

- 明确主投／拓展／冲刺岗位以及为什么匹配。
- 用项目地图说清每段经历的业务闭环和本人边界。
- 看懂面试必需的行业链路、核心指标和术语。
- 不从零起草：每题已有个人主线、具体素材和半成品模板。
- 不照抄 AI：每题保留“我的逐字稿”，并明确改写、录音和脱稿标准。
- 知道哪些细节仍需补证，哪些团队结果不能认领。

学生端不是审计报告，也不是完整标准答案。事实风险应转化为请补项、答题提示和面试前任务。

## 五、双端一致性

- 两端题目标题、分类、编号和顺序完全一致。
- 老师题卡字段：考察目标、合格回答要素、候选人可用素材、参考回答方向、继续追问、常见问题、反馈建议。
- 学生题卡字段：考察点、你的答题主线、可用素材、参考模板、我的逐字稿、答题提示。
- 同一题的候选人素材应指向同一段经历，但表述服务不同角色；不能把老师卡机械改字段后复制给学生。
- 学生模板不能连续三题复用相同内容；老师参考方向也不得只有概念定义。

## 六、阅读顺序与视觉呈现

文档必须遵循“先定位、再看懂项目、最后模拟”的阅读顺序。架构图承担教学作用，统一放在问题区之前；可以集中成一个“核心项目架构”章节，也可以紧跟对应项目，但不能放到 20 多道题之后作为附录。

通用视觉判断、信息层级和 `visual_contract` 使用 `visual-document-delivery`；本合同是更严格的领域适配。发生差异时，以本合同的双端隔离、题前位置、三档 JD、指标扫盲、职责边界和飞书验收规则为准，不能用共享合同的通用允许项降低现有标准。

飞书正文按以下形态组织：

1. 页面原生标题是整页唯一的文档级标题；正文不要再重复同名一级标题。
2. 标题后第一个正文块仍为原始简历附件；附件后只放一个结论型引用块，说明主线与事实边界。
3. 表格只承载档位、映射、任务等短字段；项目解释与答题内容使用短段落。项目章节使用稳定的组合：`一句结论 → 证据短表／卡片 → 紧邻的必要图解 → 职责边界与 Open`。不把所有长表放在前面、所有图片集中到后面。
4. 每个前置章节只完成一个任务：核心定位负责总体判断，`三档匹配 JD` 用三张一一对应的 90%／80%／70% 卡片同时讲“投什么、岗位每天做什么、为什么匹配”，项目地图负责“做过什么”，指标扫盲负责“数字到底什么意思”，架构图负责“业务／系统怎样运转”，题卡负责“怎样证明”。不得把档位和三张 JD 再拆成两个章节。
5. 用户点名要图的核心项目，以及复杂业务闭环、多角色／多系统协作、分支判断、循环回流与失败回退，一律使用真实流程图或飞书画板；普通定义与简单线性步骤不为装饰强行画图。
6. 每张图前写“看什么”，图后写本人负责、团队负责、`Open` 和对应题号；图中训练用复原必须标明不代表真实公司内部系统。
7. 同一份文档的图使用统一的横向／纵向阅读方式、角色颜色语义、标题和图例。个人动作、团队／系统和 `Open` 的颜色语义不在同页内反复更换。
8. 图解采用事务门：先生成、导出并目视确认可读，再插入正式飞书页面。生成失败、空 token、坏链接、零尺寸图像和“待插入图片／待补图／图片生成中”占位都不得进入正式页。必需图未成功时，页面可以保持无坏图，但整项交付仍为未完成。
9. `visual_contract` 记录必需图、目标章节、事实边界、媒体读回和最终页级验收；共享 manifest 通过不能替代老师／学生边界、问题区前置与远端 XML 校验。

老师版推荐顺序：快速上手 → 岗位与证据 → 履历拆解 → 项目与指标 → 项目架构图 → 模拟流程 → 问题 → 反馈。学生版推荐顺序：使用说明 → 核心定位 → 项目与术语 → 项目架构图 → 问题 → 任务。

## 七、公司专岗分流

公司、岗位、JD 或面试邀约已经明确时，使用 `student-role-interview-prep` 建立独立专岗页；不把公司调研、专岗题或下一轮准备插入通用双端。通用页可以保留已经存在的真实岗位证据，但本次专岗请求不授权重写它。

## 八、飞书写入前与最终读回质量门

飞书写入前先在当前任务中逐项回答；写入后根据远端读回再回答一次：

- 删除姓名后，这份文档是否仍能从经历、业务和风险看出属于当前学生？
- 老师能否在 5 分钟内看懂候选人并直接开始一场有节奏的模拟面试？
- 学生能否不从零起草，又不会误把 AI 模板当成自己说过的话？
- 每段核心经历能否被追到个人动作、产物、Bad Case 和职责边界？
- 两端题目是否逐题一致，且没有老师端字段泄漏给学生？
- 是否存在把团队成果、行业知识或推测写成学生亲历？
- 每个课后任务是否有交付物和验收标准？
- 项目架构图是否位于问题区之前，且页面没有“原生标题 + 重复正文 H1”？
- 两端是否都只有一个 `三档匹配 JD` 章节，三张卡是否按 90%／80%／70% 与岗位一一对应、字段齐全且顺序一致？
- 已有岗位信息、指标扫盲、附件、媒体与手工内容是否与写前保留清单逐项对应？
- 页面是否使用结论、短表／卡片、就地图解和边界说明的稳定组合，而不是前面全是表格、后面变成图片墙？
- 学生版是否覆盖所有在 JD、项目、数值成果和题卡中出现的关键指标，且至少三张指标卡逐张包含大白话、算法／判断、重要性、误判和候选人边界？非常见指标是否用 `【指标：名称】` 建立了可校验引用？
- 是否存在未解决图片占位、空 token 或未通过预览的媒体？
- 用户未授权时，新增正文、题卡和任务是否都未扩展到作品集策划？

任一项答不上来，继续补充或显式标记 `Open`；最终读回不通过不得宣称完成。
