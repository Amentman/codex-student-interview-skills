# 学生作品集产品方案

## 核心原则

把学生真实接触过的业务任务，整理成一套学生能够照着执行的完整作品集规划包。Agent 负责把方向、PRD、UI/UX 和验收门槛做清楚；学生负责开发、调试、真实调用、测试、复盘和讲解。规划包的专业感来自真实问题、证据链和可执行性，不来自功能堆砌、虚构指标或替学生做完成品。

## 开始前

先锁定学生、最新简历、目标岗位/JD、真实业务素材、既有作品和本次交付阶段。列明：本轮会产出什么、只读核对什么、明确不碰什么。

建立事实账本：

| 类型 | 可用于 |
|---|---|
| `Confirmed` | 学生本人做过的动作、结果和责任 |
| `Externally verified` | 公开公司、岗位、平台与 API 事实 |
| `Inferred` | 有依据但仍需核对的判断 |
| `Knowledge supplement` | 方法、行业知识与教学示例 |
| `Open` | 缺失、冲突或待学生确认的内容 |

规划中的 Demo 只能写成个人延伸实践、作品集或实训计划。开发、测试和学生讲解验收完成前，不得写成公司内部系统、上线成果或学生已取得的业绩。

## 四步规划交付

“完整交付”在本技能中固定指以下四件套，不包括 Agent 代替学生开发源码。四项应一次性形成可以直接发给学生的完整规划包；只有学生身份、业务方向、事实边界或飞书目标仍有关键歧义时才停下。

### 第一步：前置资料与学习任务

复用已有 SOP 的基础资料，不重复另造课程。需要资料清单或学生分层时，先按 [references/source-sop.md](references/source-sop.md) 只读回读权威飞书页面当前版本。

Agent 交付：按学生基础筛选后的学习资料、建议顺序、完成标准和一个 WorkBuddy/Codex 小任务。学生执行“读取现有项目 → 修改一处 → 重新运行 → 截图并说明变化”。T1/T2/T3 只改变脚手架数量，不改变学生必须亲自操作和解释的要求。

### 第二步：完整 PRD

从目标岗位和学生真实工作流反推产品，产出可直接交给学生执行的完整 PRD 正文。逐项填写 [PRD 十二槽位](references/product-plan-contract.md#完整-prd-十二槽位)，其中包括学生开发路线、技术建议、数据准备、Prompt 迭代和每阶段任务；不能用一页方向摘要代替。没有真实 JD 时标注代表性岗位画像。默认一个用户、一条流程、一个核心结果，控制在 1–3 周。

### 第三步：UI/UX Demo

Agent 根据 PRD 产出可操作、可审阅的 UI/UX Demo，作为学生开发时的界面与交互基线，不把它冒充已完成产品。页面顺序跟随用户任务，不跟随技术模块；默认桌面端证据工作台。Demo 覆盖正常、空、错、加载、成功、待复核和失败状态，并为每个页面标明输入、操作、输出和下一步。

### 第四步：验收标准

Agent 交付逐项验收清单，告诉学生做完后需要提交什么证据、怎样测试、什么算通过。至少覆盖：新环境运行、真实程序调用、正常/无效/失败路径、来源回查、人工修改、导出/恢复、Prompt v1/v2、3 个 Bad Case、README、数据边界和学生现场修改讲解。此步是标准与检查方法，不是 Agent 本轮替学生完成验证。

## 责任边界

| Agent 本轮交付 | 学生后续亲自完成 |
|---|---|
| 前置资料和学习任务 | 阅读资料并完成工具小任务 |
| 完整 PRD、产品/技术架构和执行步骤 | 准备数据与样本，按 PRD 开发 |
| 可操作 UI/UX Demo | 将 Demo 落成可运行产品并自行修改 |
| 验收清单、测试用例和证据要求 | 真实调用、调试、测试、Bad Case、复测、README 与答辩 |
| 飞书规划页及写后回读 | 在同一页面或约定位置提交阶段成果 |

## 产品方案合同

方案必须闭合：

`来源/输入 → 样本准备 → 规则或 AI 处理 → 带证据结果 → 人工复核 → 可用业务产物 → 测试/反馈回填 → Bad Case 修正`

只到“洞察展示”或“内容生成”不算闭环。任何 AI 结论都能回查来源；人工修订保留版本；规则处理确定性判断，AI 处理不确定任务，事实、合规、预算、发布和最终业务决定由人确认。

完整输出结构、页面状态、数据对象、技术边界和逐项验收见 [references/product-plan-contract.md](references/product-plan-contract.md)。需要具体质量形态时再读 [references/worked-example.md](references/worked-example.md)；示例是结构参考，不是可复制成学生经历的事实。

## 决策规则

| 条件 | 处理 |
|---|---|
| 真实业务素材不足 | 缩小结论，使用公开或明确模拟的小样本，保留来源与边界 |
| AI 对核心结果没有必要性 | 用规则/人工完成，不强行接模型 |
| 方案包含“AI 能力” | 在 PRD 和验收标准中要求学生完成一次真实 SDK/API/MCP/本地服务调用及失败复现 |
| 一周首版 | 给学生锁定单流程、核心页面、演示模式和一条真实调用任务；推迟登录、数据库、爬虫与自动发布 |
| 计划进入简历 | 先确认代码可运行、接口可调用、失败路径可复现、数据边界清楚，且学生能现场解释和修改 |

## 最终表达

先给推荐方向与取舍，再给证据。明确区分：Agent 本轮已交付的规划材料、学生尚未执行的任务、未来验收证据和 `Open`。不得把 PRD、UI/UX Demo 或计划中的功能写成学生已完成的产品、真实调用或业务结果。

## 飞书交付

本技能的四件套规划包默认落在该学生唯一飞书主页或用户指定文档下的独立子页面，而不是覆盖通用面试、职业规划、课程或其他受保护页面。

只有当前任务已明确授权写入且学生入口唯一时才执行：先用 `lark-cli` 解析 URL、标题、对象类型、父级、唯一性和当前修订；再创建或更新 `姓名｜作品集产品方案｜项目名` 子页面，放入前置资料、完整 PRD、UI/UX Demo 入口、学生执行任务、验收清单和 `Open`。源码、真实调用和测试结果等学生尚未完成的材料只作为待提交项，不得预填成已完成证据。写后重新读取标题、父级、修订、目录、正文、附件、链接和学生可见效果。

若学生主页、目标文档或身份不唯一，停止外部写入，先完成本地/对话版并把冲突压缩成一个待决问题；不得把资料写进本 SOP 页面或其他学生页面。
