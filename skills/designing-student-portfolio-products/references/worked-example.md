# 结构示例：跨境内容证据工作台

这是用于理解结构的代表性示例，不是任何学生已完成的经历，也不能直接复制到简历。

## 定位

为跨境内容运营岗位设计一个单 SKU 内容证据工作台。第一版只处理一个国家、一个祛痘产品和一组公开短视频样本，把来源观察转成脚本与达人 Brief，再记录测试和 Bad Case。

## 四步交付映射

1. **前置资料**：给学生 AI Coding 基础资料、工具小任务、学习顺序和完成证明要求。
2. **完整 PRD**：为学生锁定单 SKU、公开样本、内容产物、非目标、数据关系、技术方案和执行任务。
3. **UI/UX Demo**：Agent 交付可操作的桌面端证据工作台原型，作为学生开发基线。
4. **验收标准**：要求学生完成真实调用、正常/异常/失败路径、3 个 Bad Case、构建与浏览器操作，并现场修改重跑。

## 主流程

```text
SKU 与市场事实
  → 20–30 条公开样本及人工标签
  → AI 提取钩子、痛点、场景、卖点、CTA 和风险
  → 每条洞察关联样本编号
  → 人工确认功效与合规边界
  → 生成并编辑 3 套脚本和达人 Brief
  → 回填测试观察
  → 记录 Bad Case，修改规则或 Prompt 后复测
```

## 页面地图

1. **项目定义**：国家、品类、SKU、人群、卖点事实和禁止表达。
2. **样本库**：链接、平台、日期、可观察字段、公开/模拟标识和选择状态。
3. **AI 洞察**：结论、证据片段、样本编号、风险与待确认项。
4. **脚本工作室**：钩子、镜头、口播、CTA、人工修改和版本。
5. **达人 Brief**：人设、任务、必须表达、禁区与验收标准。
6. **测试复盘**：观察结果、失败样例、修改动作和复测状态。

首屏采用桌面端证据工作台：左侧固定业务流程，中间处理当前任务，右侧显示来源和风险。视觉可使用“样本编号、田野笔记、人工复核章”等业务符号，避免做成通用 AI 聊天页。

## 数据关系

```text
Project
└─ SKUProfile
   └─ Samples[]
      └─ Insights[] + sourceIds[]
         └─ Scripts[] + revisions[]
            ├─ CreatorBrief
            ├─ ReviewDecisions[]
            └─ TestRuns[] → BadCases[]
```

## PRD 中给学生的技术方案

- 桌面端 React + TypeScript + Vite；若已有项目技术栈则优先沿用。
- 前端保存项目状态，支持 JSON 导入、导出和恢复；首版不做登录和数据库。
- 服务端代理模型请求；Key 只在环境变量中。
- 模型返回结构化 JSON；解析失败显示原始错误，可重试或切换演示模式。
- 演示模式使用固定样例并持续显示“演示数据”。
- 洞察和脚本携带样本编号；高风险表达未完成人工复核时禁止导出。

## 学生落地后的验收重点

- 无 Key 的固定演示闭环和有 Key 的一次真实调用分别通过；
- 空输入、错误格式、超时和无效返回提示清楚；
- 洞察、脚本和 Brief 都能回查样本；
- 人工可编辑、确认风险并留下版本；
- JSON 导出再导入保持内容、引用与状态一致；
- 自动测试、构建和真实浏览器主流程通过；
- 学生能解释数据边界、Prompt 迭代、调用链、Bad Case 和人工兜底，并现场修改后重跑。
