# 结论先行的正式报告设计

适用于 Word、PDF、飞书文档等供 HR 或用人经理阅读的候选人审查报告。目标不是把审查过程全部摆出来，而是让读者快速决定“现在怎么处理候选人”，再按需查看证据。

## 1. 报告类型

把它当作“招聘决策备忘录”，不是审计底稿，也不是候选人画像海报。

阅读顺序固定为：

1. **现在怎么处理**：推进、定向初筛、补材料或不推进。
2. **为什么**：最多 3 个真正改变当前决策的问题。
3. **下一步做什么**：补什么材料、问什么问题、通过后去哪个环节。
4. **证据在哪里**：学历、时间线、JD 映射、项目和风险明细。

## 2. 第一页信息预算

第一页只放能在十秒内改变流程的内容，推荐结构：

```text
候选人 + 目标岗位 + 评估日期

当前建议
一句大结论

一句理由：已证明什么，但还缺什么

决定当前结论的三个问题（最多 3 个）
01 问题标题 + 1–2 句解释
02 问题标题 + 1–2 句解释
03 问题标题 + 1–2 句解释

招聘推进路径：当前阶段 → 定向核验 → 通过后的环节
一句话岗位判断
评估依据与外部核验边界
```

不要在第一页放：完整时间线、完整 JD 表、项目逐条审查、大型风险矩阵或方法论说明。第一页内容不足时增加留白，不用次要信息填满。

## 3. 三类问题必须分开

| 类型 | 含义 | 首页表达方式 |
| --- | --- | --- |
| 基础材料缺失 | 学校、学历、日期、项目归属等不足，导致背景或时间线无法确认 | “先补材料/流程门槛未过” |
| 岗位核心证据缺口 | 简历没提供目标岗位关键职责的直接证据 | “需要定向核验”，不能写成“不会” |
| 显著待核验矛盾 | 时间、职位、结果或贡献归属出现真实冲突 | 说明冲突和替代解释，不能直接写“造假” |

例如“没写学校”是重要的基础材料缺失，会阻断学历核对；它不是院校层级问题，也不是已经确认的学历不实。

## 4. 后续页面的推荐顺序

1. **基础筛查**：学历、专业、证书、时间线、Gap 和重叠。
2. **岗位匹配**：只展示会影响筛选的核心能力域；次要 JD 合并。
3. **项目与经历证据**：最强证据优先，每段说明最低能力信号、决策价值、Open 和核验方式。
4. **真实性与水分风险**：表达空泛、贡献归属、真实矛盾分开。
5. **面试核验清单**：按优先级给主问题、追问、通过信号和风险信号。
6. **结论边界**：Fact / Inference / Open / External。

单候选人报告通常控制在 4–6 页；材料复杂时可增加页数，但不能靠缩小字号或塞满表格压页数。

## 5. 表格与正文的分工

表格只用于需要跨行横向比较的内容，例如时间线、核心 JD 映射和问题优先级。

- 叙述性项目分析使用短段落或条目，不把长句塞进四列以上的表格。
- 同一页原则上只保留一个主要比较表；连续两页都是密集表格时，应改写或拆分。
- 单个表格优先 3–4 列；超过 5 列通常说明信息层级没有整理好。
- JD 映射只保留会改变筛选结论的要求，通常按 4–8 个能力域聚合。
- 不重复：同一缺口在首页、JD 表和风险页分别承担“决策、证据、核验”功能，不复制同一段话。

## 6. 视觉层级

使用一个主色和一个风险色即可。推荐黑灰为正文，深蓝或深灰为结构色，克制的深红用于决策与最高优先级。

- 红色只用于“当前建议”、关键编号、P0 标签或短句；不用整块纯红色单元格。
- 风险底色使用极浅红或浅灰，文字保持深色；不要靠饱和色面积制造严重感。
- 标题层级由字号、字重和留白建立，不靠多种底色、圆角和装饰条堆叠。
- 正文字号以舒适阅读为准；表格可以略小，但不得为了塞内容降到难读尺寸。
- 元信息弱化；建议、理由和下一步必须比候选人资料表更醒目。

## 7. 分页规则

先排内容层级，再处理分页：

- 第一页完成决策闭环后主动分页，不让第二章被动挤在页尾。
- 章节标题后至少保留一段正文；不要出现标题孤悬页底。
- 表头跨页重复；能完整放到下一页的小表不要从页底硬拆。
- 不留只有 1–3 行正文的孤页，也不留意外空白页。
- 除有意设计的决策页外，单页有效内容明显不足约四分之一时，应回调段距、分页点或前后章节分配。

## 8. 逐页验收

导出或渲染后逐页检查，不以“文件能打开”作为完成标准：

1. **十秒测试**：只看第一页，能否复述当前建议、三个以内的原因和下一步。
2. **扫读测试**：只看标题、粗体和表头，能否理解报告主线。
3. **颜色测试**：遮住红色后结构仍清楚；红色没有覆盖大面积正文。
4. **密度测试**：没有连续密集长表；项目说明能自然阅读。
5. **分页测试**：无断表、孤行、稀疏尾页、页码异常和意外空白页。
6. **边界测试**：所有“不匹配、风险、不推进”都能追溯到材料或明确标准，且未把 Open 写成事实。

发现任何一项失败，回到源文档修改并重新渲染；只有逐页检查通过后才交付。
