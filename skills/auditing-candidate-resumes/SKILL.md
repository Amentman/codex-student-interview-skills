# Auditing Candidate Resumes

## Core Principle

审查简历能评估“证据强度和待核验风险”，不能仅凭简历证明真实能力或造假。将每个结论分为 **Fact / Inference / Open / External**，并把关键判断连回简历原文。

## Route the Request

- 有 JD 或明确岗位：审查岗位匹配、硬门槛与证据。
- 无 JD：只做简历完整性、时间线、证据质量和水分风险审查；把岗位匹配标为 `Open`，不猜一个通用标准。
- 多份简历：先用同一岗位标准分别审查，再横向比较；不能为了排序改变标准。
- 候选人修改简历：转用 `building-resume-interview-stories` 或 `revising-and-delivering-resumes`。

执行审查前，完整阅读 [audit-framework.md](references/audit-framework.md)；起草结果前，完整阅读 [output-contract.md](references/output-contract.md)。若交付 Word、PDF、飞书文档或其他正式报告，还必须完整阅读 [decision-first-report-design.md](references/decision-first-report-design.md)，并使用对应的文档交付 Skill 完成制作与渲染验收。

## Required Workflow

1. 记录输入范围、资料截止时间、缺失的 JD/标准，以及是否允许外部核验。
2. 逐项提取学历、专业、证书、工作、项目和日期，重建按月时间线。只有年份时标注日期精度不足，不计算虚假精确的 Gap；保留原文的“至今”，在范围中另标截止日期。
3. 区分硬门槛的 `满足 / 明确不满足 / 未提及`；“未提及”不等于“不具备”。
4. 逐段检查本人角色、实际动作、决策边界、项目复杂度、指标口径、因果关系与前后一致性。
5. 把“水分”拆成表达空泛、贡献归属不清、真实性矛盾三类；对每个信号给出可能的无恶意解释和核验问题。
6. 按招聘决策影响排序，而不是按简历章节顺序罗列。首页只保留最多 3 个真正决定当前结论的问题；把基础材料缺失、岗位证据缺口和真实性矛盾分开，不混写成“高风险”。
7. 给出建议、下一步动作与信心等级，并说明什么新证据会改变结论。

## Non-Negotiable Boundaries

- 不把学校、专业、Gap、短任期或表达普通直接当作能力差、不稳定或造假。
- 不把“暂时无法核验”改写成“不可信”，也不因风险信号自动淘汰。
- 建议不推进时，必须基于明确不满足合法硬门槛、对核心 JD 标准完全缺乏可用证据，或已有可靠外部证据证明重大不实。这是基于当前证据的流程建议，不是对候选人能力或人品的事实判定。
- 不推断疾病、婚育、家庭责任、政治立场、民族、宗教、残障、性别、年龄等敏感特征，不用这些做排序。
- 学历、公司、职位和业绩的真实性只有在获得授权并读取相应外部证据后才可标为 `External`。

## Completion Gate

交付前确认：时间线无遗漏；学历/专业相关性与能力分开；每个高风险判断有原文、替代解释和核验问题；未提及项仍是 `Open`；最终建议没有超出当前证据。

正式报告还要通过“十秒首屏”验收：读者无需翻页即可看懂当前建议、最多 3 个决定性问题和下一步动作。逐页渲染检查视觉层级、断表、孤行、稀疏尾页和意外空白页；没看过渲染结果，不得宣称文档已完成。

## Common Mistakes

| 错误 | 修正 |
| --- | --- |
| 把简历陈述当成已验真事实 | 标为 `Fact`，只有真正外部核验后才标 `External` |
| 把“没写”当成“不会” | 标为 `Open`，改成核验问题 |
| 把风险信号直接变成淘汰 | 先看是否触发硬门槛或核心证据门槛，否则定向核验 |
| 把文案漂亮或名校背景当成能力 | 按可追问的行为、决策、结果与岗位映射判断 |
| 用大面积红色或长表制造“重点” | 红色只标结论和最高优先级；用首页决策路径、短段落和留白建立层级 |
