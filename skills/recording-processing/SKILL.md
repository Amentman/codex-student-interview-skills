# 录音处理（通用版）

**路由边界：** 用户要复盘真实公司／正式面试、逐题分析学生回答或生成下一轮训练任务时，使用 `student-mock-interview-delivery`。除非用户另行明确要求知识库沉淀，本 Skill 不自动把面试逐字稿写进六大库。

> 版本：v1.0 学员版（由寂辉实战版提炼）
> 一句话：你只管说话录音，转写稿丢给我，有价值的信息自动进你的知识库。
> 配套：知识库结构由「知识库采访机器人」生成（六大库）；沉淀的素材供「朋友圈文案」等写作 skill 取用——**库越厚，AI 写得越像你**。

---

## 第 0 步：定位你的知识库（首次使用必做）

1. 问用户：「你的知识库在哪个文件夹？把路径发我。」（已经知道就跳过）
2. 读一遍知识库目录结构。默认按六大库分流：
   - `01-老板说明书` / `02-产品库` / `03-客户需求库` / `04-素材案例库` / `05-方法论库` / `06-内容生产库`
3. 结构跟六大库不一样？**按用户的实际结构来**，找每类信息「最该待的位置」，不硬套。
4. 建议用户把知识库路径写进 AI 必读文件（CLAUDE.md / AGENTS.md），以后不用每次说。

## 模式判断（读取输入后先做）

| 模式 | 输入特征 | 处理深度 |
|------|---------|---------|
| **A·重度** | 长录音转写稿：开会、见客户、上课、听分享、咨询交流（通常 30 分钟以上） | 完整提取＋整理稿＋分流入库 |
| **B·轻量** | 碎碎念、语音备忘、走路时随口说的想法（几分钟） | 快速归纳，有价值才入库 |

判断后告知用户：「这份我判断走【A／B】模式，可以吗？」

**A 模式再分一层侧重：**
- **自己主讲**（你开会布置、给客户讲方案、答疑）→ 重点提取：你的观点、方法、案例、待办
- **别人分享**（听课、听同行交流）→ 重点提取：对方的方法怎么迁移到你的业务、给你的启发

**A 模式视觉触发：** 转写稿包含三个以上相互连接的阶段、角色交接、决策分支或多个知识去向时，**REQUIRED SUB-SKILL:** Use `visual-document-delivery`。只依据转写证据规划关系图；碎片化表达不足以证明关系时保留 `Open`，不自行补链路。

**B 模式视觉豁免：** 除非用户明确要求视觉总结，否则不加载共享视觉流程，内部记录 `no_visual_reason: 轻量语音备忘，没有需要图解的复杂关系`，保持快进快出。

## 五步流程

### 第一步：读取

用户粘贴转写稿，或给文件路径。多份转写稿就一份一份处理，不混着来。

### 第二步：通读全文，提取六类要素

**必须完整读完再动手**，不许读一段整理一段。

| 要素 | 是什么 | 举例信号 |
|------|-------|---------|
| **观点判断** | 你想通的事、做出的判断、新发现 | 「我觉得……」「我发现……」「其实关键是……」 |
| **方法经验** | 可复用的做法、流程、判断标准 | 「我一般是这么做的……」「先……再……」 |
| **故事数据** | 真实经历、具体数字、踩坑教训 | 时间、金额、客户数、失败经过 |
| **客户原话** | 客户/学员说的原话：痛点、异议、好评、常见问题 | 「客户说她最怕……」——**原话照抄，不美化** |
| **选题灵感** | 能展开成朋友圈/笔记/文章的点 | 反常识观点、有情绪的故事、高频问题 |
| **待办事项** | 明确要做的事、要联系的人 | 「回头我要……」「记得给他发……」 |

### 第三步：输出整理稿

保存到 `知识库/00-录音整理/`（没有就新建这个文件夹），文件名：`YYYY-MM-DD-主题关键词.md`

```markdown
# 标题（场景＋主题）

> 时间：YYYY年M月D日
> 类型：会议 / 见客户 / 上课 / 语音备忘
> 参与人：（有就写）

## 一、核心内容
（这段录音在说什么，3-5 句讲清）

## 核心关系图（A 模式按需）
（仅当存在复杂关系：决策—行动—负责人链路、角色交接、时间线或知识分流图）

## 二、观点与方法
（提取到的判断、方法、经验，一条一条列）

## 三、故事与数据
（原汁原味保留：具体经历、数字、案例细节）

## 四、客户原话
（原话照抄，标注是谁、什么场景说的）

## 五、待办
- [ ] 具体事项

## 六、可发展的选题
（每条：切入角度＋核心观点一句话）
```

B 模式轻量化：没有的栏目直接不写，5 分钟能处理完的不花 20 分钟。

A 模式关系图放在核心摘要之后、详细观点之前。优先选择：

- **决策—行动—负责人链路：** 只有转写中明确形成决定并指派负责人时才写负责人；“可以考虑”“以后也许”不能画成已分配任务。
- **角色交接图：** 展示谁提供输入、谁判断、谁执行、谁验收；角色不明时标 `Open`。
- **时间线：** 只使用录音中明确的时间、先后关系和截止点。
- **知识分流图：** 展示观点、原话、故事、方法、产品信息和选题将进入哪个库。

图内明确区分参与者原话、AI 整理／推断、正式行动项与知识补充。客户原话不得被改写成 AI 结论，AI 归纳不得冒充发言人原意。目标 Markdown 渲染器不支持 Mermaid 时，改用紧凑关系表；不能留下无法显示的代码块。

### 第四步：分流入库（核心动作）

**判断原则**：流水账只出整理稿不入库；有真价值的信息才分流。分流是把一份录音**拆开喂到该去的地方**，不是整篇塞进去。

| 提取到什么 | 进哪个库 |
|-----------|---------|
| 客户原话、高频问题、异议 | `03-客户需求库` |
| 客户故事、成交案例、好评、踩坑经历 | `04-素材案例库` |
| 你的方法、流程、判断标准、行业认知 | `05-方法论库` |
| 选题灵感 | `06-内容生产库`（建「选题」文件） |
| 你的个人故事、价值观表达 | `01-老板说明书` |
| 产品卖点的新说法、定价逻辑 | `02-产品库` |

**入库规则：**
1. 先看目标库里有没有主题相近的文件——有就追加，没有才新建，不重复建文件
2. 每条素材末尾加**双标签**（给 AI 检索用的）：
   ```
   📌 来源：YYYY-MM-DD 某某会议录音
   🎯 应用：写朋友圈讲客户案例 / 回答客户异议（留空待补也行）
   ```
3. 待办不入库，直接在汇报里提醒用户

### 第五步：汇报

```
✅ 录音处理完成

📄 整理稿：知识库/00-录音整理/XXX.md
📥 本次入库：
- 03-客户需求库：X 条（客户原话 X 句）
- 04-素材案例库：X 条
- 05-方法论库：X 条
- 06-内容生产库：新增选题 X 个
⏰ 待办提醒：X 件（列出来）

想直接把某条素材写成朋友圈？说「用第 X 条写条朋友圈」，我调「朋友圈文案」skill 接着干。
```

## 执行纪律

1. **必须通读全文再动手**，不读一段整理一段
2. **保留原话**——用户的口语化表达和客户原话是最好的写作素材，不许翻译成书面语
3. **不遗漏具体数字、时间线、案例细节**
4. **闲聊跑题部分省略**，不硬凑
5. **禁止编造**：转写稿里没有的信息不许脑补；听不清/存疑的标「待确认」
6. **只新建和追加，禁止修改、移动、删除**知识库里任何已有内容
7. **B 模式轻量化**：快进快出，不强行提炼
8. **A 模式图解验收**：关系图紧邻核心摘要，在实际 Markdown 渲染器中检查可读性；原话、推断、行动项和知识补充边界清楚

## 模式验收样例

- **60 分钟多决策会议：** 出现多个议题、负责人、截止点和知识去向时，输出一张最能帮助执行的决策—行动或知识分流图，并保留原话与推断边界。
- **3 分钟语音备忘：** 只有一个想法和一个待办时，输出轻量摘要与待办，不生成图；除非用户明确要求视觉总结。

## 把它变成你的（配合课程实操）

拿到本 skill 后改三个地方就能用：

1. **知识库路径**：第 0 步告诉 AI 你的库在哪（或写进 CLAUDE.md / AGENTS.md）
2. **分流映射**：你的库结构跟六大库不同？把「分流入库」表格的右列改成你自己的文件夹名
3. **常用场景**：你的录音多是什么场景（门店晨会？客户咨询？直播复盘？），在「模式判断」里给 AI 补一句你的典型输入，它判断得更准

改完对 AI 说一句「处理录音」，把转写稿丢进来试一次——跑通了它就是你的了。
