# 简历交付验收合同

## 1. 验收优先级

页数、纸张和“饱满”以用户要求和版式基线为准。发生冲突时依次保护：

1. 事实真实、经历完整、责任和数字可解释；
2. 正常缩放下可读；
3. 用户指定的页数、密度和原版式。

三者无法同时满足时如实报告，不通过删真实内容、编造经历或难读排版制造“通过”。

## 2. 需求追踪表

把用户每项要求变成可查证据：

| 要求 | 文件/来源证据 | 机器检查 | 实际查看器检查 | 结果 |
| --- | --- | --- | --- | --- |
| 保留原版式 | 版式指纹与前后截图 | 纸张/页边距/表格结构 | WPS 对照 | 通过/异常 |
| 完整一页 | 原文保留表 | 页数、溢出 | WPS/PDF 页底 | 通过/异常 |
| 饱满 | 对照版/页底基线 | 底部留白 | 正常缩放人工判断 | 通过/异常 |
| 无斜体 | 源样式/用户要求 | 有效 italic 扫描 | WPS/PDF 视觉 | 通过/异常 |
| 无局部字号/字体突变 | 源 run/段落样式 | Word 段内字号、PDF/Word 字体字号漂移 | 整页 + 100% 局部对照 | 通过/异常 |
| Word/PDF 一致 | 文件血缘、母版 ID | 文本相似度 | 换行/边框/对齐 | 通过/异常 |
| 批注与红字 | 改写记录 | comment/anchor/red run | WPS 点开检查 | 通过/异常 |
| PDF 可投递 | 干净母版 | 注释/红色内容/页数 | PDF 查看器 | 通过/异常 |
| 只留最新版 | 最终目录清单 | 文件名/数量 | Finder/目录复核 | 通过/异常 |

截图中的历史验收项先登记，再对当前文件重验；不能把旧截图当本轮通过证据。

## 3. 完整性

- 必要模块、时间线、核心实习/项目和支撑目标岗的行动没有被过度删减。
- 原文保留表中每个要点都有处置；无静默丢失。
- 没有文本截断、隐藏、溢出、孤行标题、空白第二页、错位日期或失效链接。
- 两方向的公司、时间、个人动作和真实指标保持一致。

## 4. 用户要求“完整饱满的一页”时

- Word 在目标 WPS/Word 实际显示 1 页；PDF 在真实查看器显示 1 页。
- 正文最后落点进入页面下部，不存在接近半页的空白。
- 有用户接受的模板/对照 PDF 时，以其正文边界和底部留白为优先基线；建议控制在对照值约 `±20pt`，同时人工判断。
- 无对照时，A4 页底空白 `48–90pt` 仅作诊断区间，不是自动通过线。
- 最后一行、页脚和边框不贴边、不截断；字号和行距在正常缩放下可读。
- 内容不足时明确报告，不能放大样式凑页；内容过多时先改冗余表达和间距，不删关键证据链。

## 5. Word/PDF 一致性

- 同一页数、纸张、模块顺序、段落正文、日期、数字、链接和主要对齐。
- 同一方向的批注 Word、干净母版、PDF 指向同一个母版 ID/文本版本。
- 批注 Word 允许红字和批注；干净母版和 PDF 的正文必须完全对应，只是去掉审阅样式。
- 文本提取相似度建议不低于 `0.97`；差异需判断是编码/空白还是实际缺文。
- 机器文本相似不证明视觉一致，必须对照换行、列宽、边框、日期列和页底。

## 6. 机器验收

先用 `load_workspace_dependencies` 获取带 `pdfplumber`、`lxml` 和 `pypdf` 的 Python，不假定系统 Python 已安装依赖。运行：

```bash
"/path/from/load_workspace_dependencies/python3" scripts/inspect_delivery.py \
  --review-docx "/abs/review.docx" \
  --application-pdf "/abs/application.pdf" \
  --clean-docx "/abs/clean-mother.docx" \
  --expect-comments --expect-red \
  --forbid-active-italics --forbid-pdf-red \
  --forbid-word-mixed-font-sizes \
  --forbid-pdf-typography-drift \
  --expected-pages 1 --paper a4 \
  --max-bottom-blank 90 \
  --min-text-similarity 0.97
```

脚本检查：

- DOCX 包结构、批注数量和锚点 ID；
- 红字 run、有效斜体、字体，以及同一段落内正文 run 的异常字号跨度；
- PDF 每页尺寸、最后一页底部留白、页眉页脚；
- PDF 审稿注释、常见 RGB/CMYK 红色内容；
- Word/PDF 和 review/clean 的文本相似度；
- PDF 中达到最小字符数、但其字体族或字号未出现在 Word 中的异常文本组，并输出文字样本帮助定位。

字号检查默认把 Word 段内超过 `0.75pt` 的有效字号跨度、以及 PDF 中 8 个及以上字符且相对 Word 漂移超过 `0.35pt`/出现新字体族的文本列为异常。标题、角标或用户明确设计的混排需要人工裁决，不能直接忽略。脚本仍不能判断批注语义是否挂对、是否删了关键经历、所有特殊色彩空间、中文视觉效果和真实 WPS 换行。

## 7. WPS/Word 实机验收

逐方向检查：

1. 文件能正常打开，无修复提示、乱码和字体弹窗。
2. 实际页数为目标值；页面不是半页内容、空白第二页或最后一行溢出。
3. 姓名、联系方式、教育、每段经历、项目和技能完整。
4. 批注可点开，锚定范围准确；红字只覆盖实际变化。
5. 无意外斜体、隐藏文字、字体替换、蓝色选中效果和修订残留。
6. 同一正文要点的标签、正文、首行、续行字号与行高连续；局部放大到 100% 核对，不接受某半句突然变大或换成另一中文字体。
7. 标题线、表格边框、日期、岗位列、项目符号和链接位置正常。
8. 在“无标记/打印布局”下看正文页；批注侧栏导致的界面变窄不误判为页面版式变化。

记录应用名称/版本（能获取时）、查看时间、页数和异常截图/结论。

## 8. PDF 实际验收

1. 用系统预览/目标 PDF 查看器打开，并渲染整页图检查。
2. A4 尺寸、页数和页面方向正确。
3. 页底密度与 Word/基线一致，无大块空白、截断、孤行或贴边。
4. 无红字、批注气泡、Highlight/Popup、内部备注和修订痕迹。
5. 中文字体清楚，文本可复制，邮箱/作品链接有效；没有 Word 为统一正文，PDF 某句话却回退成宋体或突然增大字号的情况。
6. 与 Word 对照模块、段落、日期、数字、主要换行、字体、字号、边框和对齐；先看整页，再在 100% 缩放下逐段扫查。

## 9. 两方向/四文件配对验收

当本轮明确要求两个方向各一份 Word + PDF：

- 最终目录严格为 4 个官方交付文件。
- 每个方向恰好 1 个 Word 批注版和 1 个 PDF 可投递版。
- 两个方向的命名清楚，不互相覆盖，方向内容不串线。
- 各自 Word/PDF 同母版；两个方向共用事实一致。
- 批注数和红字数记录实际值，但不要求与另一个方向相等，也不套用历史个案数字。

## 10. 最终目录与旧版本

- 逐个列出文件名、方向、格式、母版 ID、官方/中间/旧版状态。
- 最终目录无 `测试`、`v1/v2`、`母版`、`render`、`wps_review`、锁文件或旧“终版”。
- 只有用户明确要求且文件归属已确认，才移动旧版；去向在最终目录外并可恢复。
- 不把桌面当默认交付目录；使用学生唯一目录下的明确最终交付子目录。
- 记录处理数量、备份路径和读回结果；至少核对文件名、大小，并对代表文件实际打开/读取。历史个案的旧文件数量不是新任务指标。

## 11. 完成门

以下任一项未通过，不得说“已完成”：

- 用户点名的知识库/微信/飞书来源未实际读取或没有定位记录。
- 学生、源简历、目标方向、版式基线不唯一。
- 关键事实冲突未解决，或知识/计划被写成学生经历。
- 原文要点静默丢失或未经授权删除。
- 用户要求单页时，Word/PDF 任一不是真实单页、明显稀疏、难读或截断。
- Word/PDF 内容、主要换行、边框或对齐明显不一致。
- 正文同一要点内存在未经设计的字号突变、字体回退、行高/基线异常，或机器报出字体字号漂移但未完成定位和复核。
- 批注 Word 没有真实批注/红字，批注锚点错误，或 PDF 带审稿痕迹。
- 文件血缘无法证明两者来自同一母版。
- 用户要求只留最新版时，最终目录混入旧稿/测试文件，或旧文件被不可恢复地误删。

无法通过时，报告已完成部分、原始报错/异常、阻塞条件和用户需要提供的最小信息。
